    Your trips, ready to explore

    A practical guide to Travel Planner

    Find a trip, download its guide and explore the route, places to stay and things to do. You can keep approved plans in your browser for use without an internet connection.

    Guide version 1 · 23 October 2026 · Travel Planner engine 1.22.1

    Start here

    1. Open the main page.Use the same HTTPS app and browser profile each time. A new browser may have an empty library until you request access and download plans.
    2. Get access if this is your first visit.Choose Request access by email in Download plans. Send the prepared browser request to the owner and wait for approval.
    3. Download your approved plans.Choose Check access / download, enter the password and select Check access & download. Review the proposed size, optionally expand Choose plans, then choose Yes, download.
    4. Open a trip tile.Explore Map, select a place and open its Guide for activities, stays, dining, transfers and sources.
    Open Travel Planner →Prepare for offline use →

    Already have downloaded trips? You can open them immediately. Checking for updates is a separate action.

    Request access for this browser

    1. On the main page, find Download plans near the folders and sharing tools.
    2. Select Request access by email. Enter your name, a useful device label such as My phone, and the shared download password.
    3. Unlock the contact, then choose Open email app. Review the prepared message and send it yourself. If your mail app cannot handle the link, use the offered email draft or copy the request information.
    4. The owner reviews the request and explicitly chooses which plans to share.
    5. After the owner confirms successful publication, return in this same browser/profile and download.
    1 · You requestName, label and public browser key
    2 · Owner decidesSelected plans; Accept or Decline
    3 · GitHub publishesEncrypted access for your browser
    4 · You downloadYour browser key + password unlock it

    A device label helps the owner recognize a request. The actual access key belongs to the browser profile; the app does not read a permanent hardware ID or prove who owns the device.

    Sending an email does not grant access. Do not send your password, a GitHub token or private key to the owner. The prepared request contains public key information only.

    Download new or updated plans

    1. Select Check access / download on the main page. In Download / update plans, enter the password and select Check access & download.
    2. The app checks your encrypted access and plan metadata. This small check happens before the plan-file confirmation.
    3. Review Download these plans?: it lists how many plans/pages differ and the expected package size. Expand Choose plans to check or uncheck individual trips; Select all and Select none are available. The package size changes with your selection. Expand Files to update for individual files.
    4. Choose Yes, download to transfer the changed pages, or No, keep current plans to leave your previous offline plans unchanged.
    5. Keep the page foregrounded until completion. Progress shows 0–100% and kB or MB. Open a downloaded tile to verify it.

    In the public HTTPS app, the package size describes encrypted plan-file bytes, including encryption overhead. In an owner’s separately configured private local copy, the size instead describes decoded plan-file content bytes; its action labels can read Download / update and Download updates. The dialog states which size basis applies. Network headers and compression can make actual data usage differ. An “up to date” check may download metadata while transferring no plan pages.

    Downloaded pages are verified before the app replaces the saved collection. Failed or cancelled updates retain the previous offline plans. If no pages differ, there may be no Yes/No prompt.

    Download choices are remembered in this browser; newly available approved plans start selected. Unchecking a plan skips its download/update and keeps any saved version with its matching description. Choices do not change owner approval. New plans become available automatically only when the owner enabled future-plan access; otherwise ask the owner to add them. If browser settings block saving preferences, the dialog says the choice applies only to the current page.

    Find and organize your trips

    Main-page controls
    ControlWhat it does
    Search tripsFilters the saved library by trip/destination information. Searching inside a particular map is separate.
    All trips / Favorites / TrashChanges the current collection. Use the star on a tile to add or remove a favorite.
    FoldersCreate and rename your own groups. Move a trip with drag and drop, or use Move… on touch/keyboard.
    Trash / RestoreHides a trip from active collections; Restore brings it back. This is not permanent deletion of the source guide.
    SortNext trip first is the default: ongoing trips, upcoming departures, then recent past. Date order and A–Z / Z–A are available.

    Favorites and folder membership are independent. Removing a folder keeps its trips in All trips. Your organization, view and sort preferences are saved in this browser; they do not automatically synchronize across devices.

    Choose PC or smartphone view

    The main-page View selector offers Auto, PC and Smartphone. Auto uses screen/pointer characteristics to choose an appropriate layout; a manual choice is remembered when browser storage is available. Plan headers also provide a view-switch option.

    On a computer

    The map sits beside the guide. Search, activity shortcuts and matching locations stay anchored above the scrolling planning/detail content. Recommended routes and longer optional sections start compact or collapsed.

    On a phone

    Plans start on Map. The compact controls above it contain the route selector, Tools, Plan, search/topic selection and a horizontally scrollable activity row. Bottom navigation has only Map and Guide.

    Use Tools for map layers and secondary commands. Use Plan to expand preferences, route recommendations and transfers while keeping map context. Selecting a place keeps Map visible and shows a preview; choose Open guide when you want its full details.

    Use Dark mode / Light mode for the saved theme choice. Pinch zooming the actual map differs from your browser's text/page zoom.

    Explore the map and local minimaps

    Local minimaps open in Street view using the saved background when offline. Overview and Satellite remain available; your manual layer choice stays in effect while using the guide.

    • Select a place: click/tap its dot, a search result or an itinerary stop. On a phone, tap opens a compact extended preview; Open guide is a separate action. The preview uses the available height above navigation, with smaller imagery and controls. Typical content fits without scrolling; long descriptions or enlarged text retain a scrolling fallback, with guide/dismiss actions reachable.
    • Move and zoom: drag the map, use its zoom controls, or use supported wheel/pinch gestures. Touch-pan alternatives are available in the tools. The scale bar changes with the displayed extent.
    • Background: choose Overview, Street or Satellite. Saved offline views cover their original extent/resolution; use live views for additional online detail where the provider is available.
    • Climate / Weather: these are separate views. Selecting a place can restore the underlying geographic map when an overlay was covering it.
    • Labels and legend: optional labels can appear as you zoom; dots remain selectable. Expand the legend or credits when needed.
    • Reference photos: open a gallery image to inspect it and its credit/source. A seasonal or historical photo is not proof of present conditions.

    Reset map focus (↺): the button below zoom-out clears activity/query matches and the selected-place preview, then restores the whole-trip map extent. Your chosen route, background and saved trip data remain unchanged.

    At a selected location

    The shared local minimap combines activities and accommodation points where coordinates are verified. Zoom and drag it independently. On desktop, hover or select an element for its larger preview; on touch, tap it. Precise entrance locations may be unverified or an area may be approximate—read the scope note and practical access information.

    Route lines and displayed straight-line distances are planning illustrations. Follow the named transport/access instructions and a suitable navigation service; the app is not turn-by-turn or emergency navigation.

    Search across places, activities and mobility

    Inside a trip, use Search places & activities. The topic selector can search All topics, Places, stays & dining, Activities, or Mobility & transfers. Activity shortcuts are based on that plan's interests.

    Search patterns
    TryMeaning
    rental carAll words must match information associated with the same location, across the selected topics.
    hiking, gardensCommas mean alternatives. | and or also mean alternatives.
    Activity shortcutHighlights locations matched to its curated activity tag. A matching result can explain which topic matched.

    Select a result to locate it on the map. On mobile, use the preview's Open guide button for the full stop. If nothing matches, clear the query, try fewer words or switch to All topics.

    Search reads the saved research; it does not search the internet or refresh a source's check date. Read the matched text: a transfer discussion can mention a vehicle without recommending it.

    Read and highlight recommended routes

    Open the Recommended routes field (or Plan on a phone), then select Prio 1 or Prio 2. Some guides have an additional researched priority. Each option has its own dated sleeping-night itinerary, trade-offs and conditions.

    • Prio 1 is the first evaluated itinerary, not a booking. The map opens with All routes highlighted; select an individual route whenever you prefer.
    • Use the route selector or highlight action to emphasize its connections; All routes shows the alternatives together.
    • The itinerary shows transfers and recovery/weather flexibility. A map full of activity pins does not mean all of them fit into one day.
    • Read the complete route and final departure transfer. Provisional dates, gateways and timetables must be resolved before booking.

    Planning preferences explain why the guide was created: interests, route approach and party information. Two adults sharing a room or vehicle do not pay two room/vehicle prices; per-person admissions or tickets usually apply to both.

    Use the location guide

    The selected stop's name, visit dates and short description remain available as you browse its details. Use its section links to move between activities, stay options, local map, conditions and sources.

    What to check before committing
    SectionLook for
    How to get thereNamed origin, practical transport, elapsed estimate, approach/terminal time and booking limitations—not only air distance.
    ActivitiesWhy it fits, duration/access, source, cost basis and seasonal/skill constraints. Choose alternatives according to conditions and pace.
    AccommodationTwo viable options where sensible, bedding/occupancy, location precision and the difference between a property reference and actual dated availability.
    DiningNamed branch/area, practical access, approximate meal budget, menu/allergy/booking limitations and independent check dates.
    Reviews and photosExact reviewed entity, platform, scale/count/date; exact versus regional/historical photo scope. Missing verified photos are labelled rather than replaced with unrelated ones.
    SourcesOriginal record-check dates and links. A recent presentation upgrade does not reverify old prices, stock or schedules.

    Editorial allowance means a planning estimate. Published tariff means a provider's reference price. Neither establishes seats or rooms for your dates. External booking pages remain subject to the operator's current terms.

    Weather, climate and forecast confidence

    These views answer different questions:

    • Current forecast: up to 14 days actually available from the provider, with temperature, rainfall and wind diagrams, numeric values and a retrieval date. Its dates are independent of a holiday many months away.
    • Trip-season climate: historical monthly averages or clearly labelled station/proxy context for the travel month. Monthly rainfall is for the whole calendar month, not a prediction of rain during your stay.
    • Seasonal outlook: shown only with a source, issue/validity period and scope; it is not a reliable daily forecast for a distant trip.
    • Climate map: the attributed original regional reference. It can be zoomed without pretending unverified route pins align to that image.
    • Weather map: provider layers such as clouds, rain, temperature and gusts. These need internet and use their own model times.

    Where available, confidence information uses labelled ensemble spread/coverage. Rain probability is not overall forecast accuracy. Missing uncertainty stays unknown; the app does not invent a confidence percentage.

    The side-guide Weather & conditions starts collapsed. The main Weather view opens its local forecast for inspection. Offline snapshots show their saved date; refresh needs internet and may fail without deleting the previous reference.

    Prepare for offline use

    1. While online, open the HTTPS app in the browser or Home Screen app you intend to use during travel.
    2. Download the approved plans and wait for success. Open the needed tiles and inspect saved images/maps.
    3. Turn off internet temporarily, reopen the same app/browser and check your important plan. Test again after restarting the browser before relying on it.
    4. Keep browser data and that profile. Avoid private/incognito mode for persistent travel storage.
    Offline availability
    Saved and usableStill needs internet
    Downloaded guides, supplied photos, descriptions, routes, saved Overview/Street/Satellite backgrounds and dated forecast snapshotsNew grants/updates, finer live map detail, provider weather layers, weather refresh and external booking/source pages

    The app stores plans inside the browser. It does not silently create a normal plans folder on your phone/computer. Browser storage may be cleared or evicted by settings, private mode or the operating system; it is not an indefinite backup guarantee.

    On iPhone/iPad, Safari and a Home Screen app can have different storage contexts. Set up and test in the exact one you will use. Changing device, browser/profile, app origin or clearing its key storage needs a new access request.

    Create or revise a travel plan

    Create

    Select Plan a new trip. Supply destination, timeframe, activities in priority order and either a rough route or Suggest a route. Viewpoints and Food are included as default planning interests alongside your own priorities. Nearby Lakes, Rivers and Beaches are also considered where distance and practical access fit your route or an existing base—without disproportionate detours, extra hotel changes or rushed days. These are options, not a requirement to visit every water spot; the original brief remains recorded. Add adults, children/ages and any fixed bookings, budget or bedding needs. Choose Prepare planning request, copy it and give it to Codex using the Vacation Map Planner skill.

    Revise

    Update trip inputs prepares a revised destination/date/interest request. Update features prepares a presentation/interaction upgrade and can limit its scope. Neither immediately changes the saved itinerary in the browser. Codex researches/builds, validates and re-registers the result under the same trip ID.

    Unaffected evidence and verified photos should be reused with original timestamps. Substantial updates retain a recoverable prior version. Unchanged builds should not create unnecessary backup files or pretend the research was refreshed.

    The web forms prepare a request, not a reservation or autonomous AI job. A finished new plan also needs the owner's explicit grant selection before it appears on another approved browser.

    Owner: accept or decline a request

    Use the Owner dashboard as the primary workflow. The public dashboard URL is not a management password: GitHub repository permissions authorize decisions.

    1. Open the request link from the visitor's email, or paste the structured request JSON.
    2. Connect using a dedicated fine-grained owner GitHub token. It needs private-repository Contents read and Actions read/write; the visitor download password is not this credential. Use only the trusted app URL.
    3. Select Review request, verify the person and browser label/key, then check the exact plans. New requests default to all current plans selected and Automatically include future plans enabled. Turn it off to share only the selected plans; unchecked existing plans remain excluded.
    4. Choose Accept & publish or Decline. Check publication status: queued is not completed. Successful Accept & publish needs no second update action.
    5. Use Reload records to inspect decisions. Edit plan access changes an approved browser’s selection and future-plan policy. Publish plan updates refreshes approved content and adds new plans for opted-in browsers using their existing browser keys and password. Remove future access excludes a browser from future sharing.
    6. Disconnect when finished. The owner credential stays in that tab's memory and is not embedded/persisted by the dashboard.

    Codex alternative: provide the request and explicitly say approve/decline/revoke, with the plans to share. Codex can dispatch the same private workflow using an authorized connection or local/session credential. Do not paste tokens or passwords into chat.

    Removing access cannot erase plans or keys someone already received. New browsers need approval, but a previously downloaded copy can remain usable offline. Device names are not trusted hardware identities.

    Troubleshooting

    No plans, or “No access grant found”

    Check the same browser/profile that sent the request. Ask the owner whether the exact plans were selected and publication completed. A new profile or cleared key needs a new request. Do not ask for the repository token.

    Email app does not open, or the link is awkward

    Use the offered email-draft option where supported, or copy the structured request into a new message. Review and send manually. Mail-client handling varies; clicking the email button alone does not send or approve anything.

    Incorrect password or damaged grant

    Confirm the current password with the owner privately, then retry. Do not paste it into chat or include it in the request. A changed owner password may require a fresh publication. An integrity error should not be bypassed.

    Download failed or browser storage is full

    Keep the app foregrounded, restore internet and free appropriate browser/device storage. Existing verified plans are retained after a failed update. Deleting app/browser data can also delete the approval key; use care and expect reapproval if that happens.

    Downloaded on one browser, missing on another

    Storage and approval belong to a browser profile and app origin. Repeat request/download in the intended browser. Favorites/folders need Export/Import organization if you want to transfer those settings.

    Street/Satellite or weather looks blank offline

    Use saved offline backgrounds or Overview. Fine map detail and online weather layers need internet. Saved images cannot provide detail beyond their original resolution/extent. The forecast retrieval date explains how old its offline snapshot is.

    Search has no matches

    Clear the query and use All topics. Try fewer words; comma-separated words are alternatives. Search uses saved information only, so an undiscovered venue will not appear through a live internet search.

    Owner connects, but approval gives 403

    Connecting can read metadata without permission to dispatch a workflow. Check the dedicated owner token's selected private repository, expiry and Actions read/write permission; Contents read alone is insufficient. Disconnect/reconnect after fixing it. The separate workflow publishing credential does not fix dashboard dispatch permission.

    The forecast dates are not my holiday dates

    This is intentional: the current forecast shows only the provider's available near-term dates. Read trip-season climate separately for a distant vacation; it is not a day-by-day prediction.

    Privacy, practical limits and tested coverage

    The public app serves encrypted plan files and encrypted access for approved browser keys. It does not embed a GitHub download token. The password-protected email contact can be revealed by someone who knows the password; it is not a way to keep an address secret from an authorized visitor.

    Approval binds to a browser profile, not physical hardware. Self-reported names/labels need owner verification. Public encrypted sharing still exposes metadata such as key hashes, ciphertext sizes and update timing. People with decrypted material can keep or share copies; no website can recall those copies.

    Device evidence: the owner reported working requests, grants, downloads and offline reopening after browser restart on Windows/Firefox and Android/Chrome. Browser/OS versions were not supplied. Automated and actual-browser checks cover additional implementation paths, but full physical iOS/Safari, macOS and Linux behavior is not certified. Test the intended browser offline before travel.

    Recommendations, estimated times, availability and photos retain their individual evidence limitations. Check current operator information before paying, travel and local conditions before setting out, and respect access rules.
