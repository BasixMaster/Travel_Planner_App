One-time publishing setup

The private Manage access workflow needs three repository Actions secrets before Accept & publish can complete:

  • TRAVEL_APP_PUBLISH_TOKEN: separate fine-grained token restricted to the public app repository, Contents read/write.
  • TRAVEL_SHARE_PASSWORD: your existing download password.
  • TRAVEL_SHARE_MASTER_KEY: random 32-byte key encoded as base64; keep it separate from all passwords and tokens.

Configure secrets in the private repository. Never paste secret values into request data or workflow inputs. The dashboard connection token needs Actions read/write and Contents read on the private repository.

No Cloudflare account or paid email service is needed. Existing offline plans stay available while setup is pending.

Sharing groups

Only the repository owner can create and edit groups. Choose approved browsers belonging to the people in Family, Friends or another group. Each approved member receives only the enabled groups they belong to; other members’ names and browser IDs stay private.

A person with multiple approved browsers needs each browser selected. Group changes update future published access; downloaded copies cannot be recalled. Disabled groups cannot be selected for new sharing. Save & publish queues GitHub Actions and does not finish until the publication succeeds.

Connect to manage groups.

Plan sharing policy

Owner-only plans remain available locally and through authenticated private-repository owner downloads. They are excluded from other visitors, including automatic future-plan access. An explicitly assigned, already-approved owner browser can still download its own private plans. Previously downloaded copies, keys and historical public ciphertext cannot be recalled.
